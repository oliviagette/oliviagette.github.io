Fraud Detection Analysis and End-to-End Analytics Pipeline

This project analyzes financial transaction data to identify fraud patterns, evaluate baseline machine learning models, engineer risk features, and build a complete analytics workflow from raw data ingestion to interactive dashboards. The work combines exploratory data analysis, statistical modeling, feature engineering, cloud data modeling, and business intelligence to uncover device, location, and merchant-category fraud trends.

Project Context

This project originated as a group assignment in BA5200: IS Management and Data Analytics. As a team, we performed exploratory data analysis, identified class imbalance (5% fraud), built a baseline logistic regression model, and produced the course report and presentation.

After completing the course project, I independently extended the work by building a full Snowflake + dbt + Power BI analytics pipeline, engineering new fraud-related features, and creating a multi-page dashboard. All advanced data modeling, feature engineering, dashboard development, and portfolio documentation were completed independently.

Project Overview

The goal of this project was to transform raw transactional data into actionable fraud insights using modern data engineering, machine learning, and BI tools. The workflow includes:

  • Exploratory data analysis and baseline ML modeling
  • Ingesting and staging data in Snowflake
  • Building feature-rich transformation models in dbt
  • Engineering device, customer, and behavioral risk metrics
  • Developing a multi-page Power BI dashboard
  • Documenting class imbalance challenges and model limitations
This project demonstrates end-to-end analytics capabilities suitable for fraud detection, risk scoring, and operational intelligence.

Key Features

  • Full fraud detection workflow: EDA → modeling → feature engineering → dashboard
  • Snowflake → dbt → Power BI analytics pipeline
  • Feature engineering including device_fraud_count, customer variety metrics, and velocity fields
  • Multi-page dashboard covering fraud overview, device risk, location risk, and category-level analysis
  • Interactive slicers, drilldowns, maps, bar charts, and KPI cards
  • Exploration of class imbalance and baseline model limitations

Dataset

The dataset contains over 200,000 synthetic financial transactions with:

  • Device, location, merchant category, and customer identifiers
  • Transaction timestamps and amounts
  • Binary fraud labels
  • Demographic attributes such as age group and account type
Data was loaded into Snowflake, cleaned in staging models, and transformed into analytics-ready marts using dbt.

Data Modeling Approach

The dbt layer includes:

  • Staging models to standardize raw fields and enforce data types
  • Feature engineering for device_fraud_count, customer transaction variety, and velocity metrics
  • Analytic marts for fraud overview, device risk, customer profiles, and category-level insights
These models feed directly into Power BI through Snowflake connections.

Dashboard Design

The Power BI dashboard consists of multiple pages:

  • Fraud Overview: KPIs, fraud rate, fraud amount, category-level risk
  • Device Risk: device_fraud_count, device-type fraud rates, drilldown table
  • Location Risk: geographic fraud hotspots and regional patterns
  • Category Risk: merchant category, age group, account type, and device type fraud rates
  • Customer Profiles: customer-level metrics and risk indicators
Visuals include bar charts, maps, scatter plots, KPI cards, and slicers for interactive filtering.

Results

The analysis revealed clear fraud patterns across device types, merchant categories, and geographic regions. Device-related features (e.g., device_fraud_count) provided the strongest signal for identifying high-risk behaviors. Baseline ML models achieved high accuracy due to class imbalance, highlighting the importance of engineered features and domain-driven analytics.
