Fraud Detection Analysis and End-to-End Analytics Pipeline

This project analyzes financial transaction data to identify fraud patterns, evaluate baseline machine learning models, manipulate risk features, and build an analytics workflow from raw data to interactive dashboards. The work includes exploratory data analysis, statistical modeling, feature engineering, cloud data modeling, and business intelligence to look at device, location, and merchant-category fraud trends.

Project Context

This project started as a group assignment in BA5200: IS Management and Data Analytics. As a team, we performed exploratory data analysis, identified class imbalance (5% fraud), built a baseline logistic regression model, and produced the course report and presentation.

After completing the course project, I independently extended the work by building a full Snowflake + dbt + Power BI analytics pipeline, engineering new fraud-related features, and creating a multi-page dashboard.

Project Overview

The goal of this project was to transform raw transactional data into usable fraud insights using data engineering, machine learning, and BI tools. The workflow includes:

  • Exploratory data analysis and baseline ML modeling
  • Loading in and staging data in Snowflake
  • Building transformation models in dbt
  • Writing device, customer, and behavioral risk metrics
  • Developing a multi-page Power BI dashboard
  • Documenting challenges and model limitations

Key Features

  • Fraud detection workflow: EDA → modeling → feature engineering → dashboard
  • Snowflake + dbt + Power BI analytics pipeline
  • Feature engineering including device fraud count, customer variety metrics, and velocity fields
  • Multi-page dashboard including fraud overview, device risk, location risk, and category-level analysis
  • Interactive slicers, bar charts, and KPI cards

Dataset

The dataset contains over 200,000 generated financial transactions with:

  • Device, location, merchant category, and customer identifiers
  • Transaction timestamps and amounts
  • Binary fraud labels
  • Demographic attributes such as age group and account type
Data was loaded into Snowflake, cleaned in staging models, and transformed into analytics-ready marts using dbt.

Data Modeling Approach

The dbt layer includes:

  • Staging models to standardize raw fields and correct data types
  • Feature engineering for device fraud count, customer transaction variety, and velocity metrics
  • Analytic marts for fraud overview, device risk, customer profiles, and category-level insights
These models are put directly into Power BI using Snowflake connections.

Dashboard Design

The Power BI dashboard consists of multiple pages:

  • Fraud Overview: KPIs, fraud rate, fraud amount, category-level risk
  • Device Risk: device_fraud_count, device-type fraud rates, drilldown table
  • Velocity & Behavioral Risk: visualizes high‑velocity activity and behavioral anomalies linked to fraud
Visuals include bar charts, KPI cards, and slicers for interactive filtering.

Results

The analysis showed fraud patterns across device types, merchant categories, and geographic locations. Device-related features looked to have the strongest correlation to identifying high-risk behaviors. Baseline ML models achieved high accuracy due to class imbalance, highlighting the importance of engineered features and domain-driven analytics.
