Predicting ICU Length of Stay using Spark Based Regression

This project uses Apache Spark for distributed data processing and regression modeling to predict ICU (Intensive Care Unit) length of stay. Accurate length of stay prediction is important for hospital resource planning, clinical decision support, and improving patient care strategies.

Project Overview

As part of a two-person team, this project explored how distributed computing can improve preprocessing and modeling efficiency for large-scale clinical data. Using a subset of the Kaggle HOSP & ICU dataset, we implemented regression pipelines in PySpark and compared baseline and non-linear models for predicting ICU length of stay. The project emphasizes healthcare analytics, scalable computation, and model evaluation in a distributed environment.

Key Features

  • Distributed preprocessing and modeling using Apache Spark across four virtual machines
  • ICU length of stay prediction using PySpark MLlib regression pipelines
  • Comparison of Linear Regression and Random Forest Regression models
  • Feature engineering with one-hot encoding, scaling, median imputation, and vector assembly
  • Performance comparison of 1-, 2-, 3-, and 4-node Spark cluster configurations

Dataset

The project used the Kaggle HOSP & ICU Datasets (100,000 med-data from 2001–2019) dataset, specifically the ICUSTAYS.csv file. The data included patient identifiers, ICU admission and discharge times, and calculated length of stay values. Preprocessing focused on cleaning invalid LOS values, handling missing data, and preparing features for regression.

Model Approach

Two regression models were implemented and compared using the same preprocessing pipeline. A Linear Regression model served as a baseline, while a Random Forest Regressor was used to test whether a more flexible, non-linear model could improve predictive performance. Features were assembled into a single vector, scaled with MinMaxScaler, and evaluated using RMSE and R².

Performance Comparison

In addition to comparing regression models, the project measured Spark runtime performance across different cluster sizes. The best runtime was achieved using two to three virtual machines, reducing total runtime from 1.7 minutes to 1.4 minutes, which represents roughly a 20% improvement over the single-node configuration.

Results

The Random Forest Regressor slightly outperformed the Linear Regression baseline, achieving an RMSE of 9.567 days and R² of 0.059, compared to the Linear Regression model’s RMSE of 9.778 days and R² of 0.017. While the models showed limited predictive power, the project successfully demonstrated the value of Spark for scalable clinical data analysis and identified opportunities for improvement such as log-transformed targets and hyperparameter tuning.
